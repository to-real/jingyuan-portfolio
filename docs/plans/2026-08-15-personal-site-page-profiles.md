## 1. Shared page rules

每个页面或区块必须拥有单一主要任务，并能回答一个明确的访问者问题。

成果、指标和说明性证据原则上只出现一次。导航入口与联系方式可以因使用场景不同而重复，但不重复配套说明。

页面内容应遵循以下顺序：

1. 访问者问题；
2. 最短答案；
3. 支撑答案的证据；
4. 明确的下一步操作。

## 2. Homepage hero

### Job

在首次访问的约 10 秒内，回答：“张靖远是谁，适合做什么，我接下来应该看哪里？”

### Required

- 身份与不过期的求职状态；
- “AI 产品经理”为主、“AI Builder”为辅的定位；
- 先事实、后观点的简短介绍；
- “查看项目”和“下载简历”两个主操作；
- GitHub 与 X 的次级文字入口；
- 保留漫画头像作为个人识别资产。

### Must not carry

- 独立指标条；
- 能力矩阵；
- DeepWisdom 摘要条；
- GitHub 仓库卡片；
- 详细个人经历；
- 与项目区重复的成果解释。

### Primary next step

进入精选项目。下载简历是并列的高意图操作，GitHub 与 X 的视觉权重低一级。

## 3. Selected work

### Job

回答：“他实际解决过什么问题，个人贡献和结果是什么？”

### Each core project should include

- 问题或使用场景；
- 清楚的个人职责边界；
- 关键行动、判断或实现；
- 可核实的结果；
- 进入完整案例或相关材料的入口。

### Avoid

- 只列技术栈而不解释问题；
- 把团队成果全部写成个人主导；
- 在全局区域再次展示项目指标；
- 多张卡片使用相同、空泛的价值描述。

### Primary next step

查看完整案例、仓库或可验证的项目材料。

## 4. Product perspective

### Job

回答：“他如何判断该不该做，以及做完如何验收？”

### Required

- 用具体经历解释产品判断；
- 展示约束、取舍、失败条件或验收逻辑；
- 让观点能够回到实际问题，而不是停留在口号。

### Avoid

- 抽象宣言墙；
- 重复项目区已经呈现的成果数字；
- 用复杂术语代替清晰判断。

### Primary next step

继续阅读相关项目或文章，验证观点如何落实。

## 5. Writing and open source

### Job

回答：“他是否持续思考，也能独立做出东西？”

### Required

- 文章与工具分组展示；
- 文章标题和项目名称本身是清晰外链；
- 每项用一句话说明解决的问题或阅读价值；
- 外链具有可见的默认、悬浮和键盘聚焦反馈。

### Avoid

- 只显示名称、不说明用途；
- 把项目描述写成技术栈清单；
- 使用只靠光标变化识别的链接；
- 恢复已经明确移除的 `all-agentic-architectures` 展示项，除非用户重新确认。

### Primary next step

打开文章或代码仓库。

## 6. Résumé

### Job

回答：“如何快速获得结构化经历？”

### Required

- 明确的中文简历入口；
- 清楚标明文件语言或版本；
- 下载动作与普通站内导航有可识别的差异。

### Avoid

- 在下载入口周围重复整段履历；
- 使用含糊的“了解更多”作为下载文案；
- 链接到无法访问或过期的文件。

### Primary next step

下载或查看简历。

## 7. Contact

### Job

回答：“如何联系，以及目前是否开放相关机会？”

### Required

- 邮箱是最直接的主操作；
- GitHub 与 X 是次级入口；
- 求职或合作状态使用不过度绑定具体批次的表达。

### Avoid

- 重复个人简介；
- 重复项目数据或能力说明；
- 使用只有图标、没有可访问名称的操作。

### Primary next step

发送邮件，或进入 GitHub / X 了解持续输出。

## 8. Navigation

导航的任务是帮助用户定位，不承担证据展示。

- 名称应与页面或区块职责一致；
- 当前项与聚焦状态必须可见；
- 锚点跳转后，目标标题不能被固定导航遮挡；
- 移动端导航不得改变内容的语义顺序。

## 9. Adding a new page or section

新增前必须回答：

1. 它解决哪个现有页面无法解决的访问者问题？
2. 它承载的证据是否已经在别处出现？
3. 删除它会损失什么信息或行动能力？
4. 它的主要下一步操作是什么？

若以上问题无法给出具体答案，不应新增该页面或区块。
