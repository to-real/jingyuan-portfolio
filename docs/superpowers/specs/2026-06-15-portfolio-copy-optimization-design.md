# 个人网站表达优化设计

## 目标

优化张靖远个人网站的中文表达，以国内 AI 产品经理实习和 2027 届校招为主，同时让海外 AI Product Manager / Technical PM 和潜在合作者能看懂。

本轮只优化文案、信息顺序和页面内部标题，不更换现有视觉语言，不新增无法验证的数据或经历。

## 读者和定位

首要读者是国内大厂和 AI 创业团队的产品招聘者。其次是海外 AI 产品岗位和可能的项目合作者。

三层身份不并列成标签，而是按以下关系表达：

1. 职业身份：AI 产品经理。
2. 可信度：做过 Agent 评测、生成式产品、RAG 数据产品和视觉 AI，能和算法、工程团队对齐任务、评测和交付标准。
3. 个人辨识度：会自己用产品、写小实验，并把需要弄懂的问题写下来。

## 表达语气

采用第一人称、专业但不端着的中文。参考 Zara Zhang 的是叙事方式，不是模仿她的具体句子：从亲身需求、使用体验或具体问题起笔，然后给出自己的判断。

保留：

- 具体人、任务、动作、数字和结果。
- 对产品取舍的直接判断。
- 长短不一的句子，必要时单句成段。
- “我做了什么”和“我为什么这样做”。

删除：

- “闭环”“长期能力”“从模型能力到用户价值”等代替事实的抽象总结。
- 工整的排比、对仗和品牌口号。
- 为了显得专业而叠加的 Agent、RAG、Context Engineering 等术语。
- “我关注的不是 A，而是 B”类型的反复自我定义。

## 2026 年内容侧重

当前 Agent 产品实践和岗位需求共同指向以下几项能力，网站应用项目事实来呈现，不直接写成技能口号：

- 先定义用户要完成的工作，再决定是否使用 Agent。
- 优先简单、可调试的工作流，只在必要时增加多 Agent 复杂度。
- 用评测明确“做对了”的标准，结合规则检查、模型评分和人工复核。
- 区分能力评测和回归评测，说清改版后如何防止旧问题反复出现。
- 考虑工具调用、状态、失败路径、人工接管、成本和延迟。
- 能从用户反馈和真实任务中归纳问题，再转成产品与评测要求。

## 首页信息顺序

### 1. 首屏

首屏保留明确的职业标签，但正文从一个真实、持续遇到的问题开始。

拟定表达：

> 你好，我是张靖远。
>
> 我在做 AI 产品，也一直在琢磨：模型出错之后，产品怎么把任务接回来？

补充文案直接说明项目范围和关心点，不再把个人主张包装成金句。

### 2. 数字证据

保留 200+、70%、23% 到 61%、2 项软件著作权。不给区域额外命名为 Evidence 或成果闭环，数字本身就是证据。

### 3. 项目列表

标题从“四种把 AI 变成产品的方式”改为“这几年，我主要做了四件事”。

每个项目卡片按以下顺序：

1. 公司或项目名与主题。
2. 当时要解决的具体问题。
3. 我做的 1 到 2 个核心动作。
4. 可验证的结果或交付物。

### 4. 工作方法

不用“产品判断”的姿态总结六条原则，改为“做 AI 产品时，我会反复问这几个问题”：

- 用户到底想完成什么？
- 哪些步骤用规则更稳，哪些才需要模型？
- 任务跑偏或中断后，用户怎么继续？
- 怎么证明这一版真的更好？

### 5. 构建与写作

使用已确认的表达：

> 我写的东西，大多来自我自己需要弄懂的问题。先弄明白，再写下来。

下方只列出最近在研究的问题、学习方法和代表文章，不再解释“构建和写作如何形成长期能力”。

### 6. 联系方式

直接说明当前状态：寻找 2027 届 AI 产品经理实习和校招机会，同时开放 Agent 评测、生成式产品和技术写作交流。

## 项目详情页结构

四个项目页使用同一阅读逻辑，但不强求标题和段落数量整齐：

1. 当时的问题：谁在什么情况下卡住了。
2. 我的任务：职责范围和真正负责的部分。
3. 我怎么做：调研、产品决策、数据或技术方案。
4. 关键取舍：有哪些方案，为什么没选更复杂的方案。
5. 结果：数据、交付物、上线状态或登记成果。
6. 现在怎么看：一个真实的反思，可以是局限、未验证假设或下一步会先做的事。

项目页中的英文 Schema 和模型名称仅在它们对说明方案必要时保留，不在大标题里密集出现。

## 项目页侧重

### DeepWisdom

重点保留评测 Schema、自动检查、人工复核、回归和恢复机制。表达应让招聘者看懂你如何把模糊标准变成可执行的产品要求，而不是仅列 Task / Trace / Evidence / Rubric / Judge。

### FunloomAI

重点是 20+ 用户访谈如何改变产品判断，以及从首次生成到局部修改、验收和留存的具体路径。把“自然语言到可玩原型”放在背景，把用户为什么不继续用放在中心。

### 数字媒体数据系统

重点是素材的来源、授权、使用语境和项目关系。RAG 只是检索方案的一部分，页面不应把它包装成项目主角。

### 珍珠视觉 AI

重点是从标准化采集到可解释报告和商品展示的业务流程。模型名称是支撑信息，买家、卖家和平台运营如何使用结果才是产品叙事。

## 真实性和边界

- 仅使用现有简历和网站中出现的事实。
- 数据必须保留原始口径，不把团队成果改写成个人独立成果。
- 如果某个数字无法从简历或已有资料确认，实施时不新增。
- 不把尚未实际做过的 2026 最佳实践写成个人经验。外部实践只用来决定哪些已有经历值得突出。

## SEO 和元信息

- 页面 title 保留姓名和 AI 产品经理。
- description 使用自然中文，包含 Agent 评测、生成式 AI、RAG 和视觉 AI，但不堆叠关键词。
- `llms.txt` 同步主要项目和联系信息，语气保持事实化。
- 导航中的“写作”保留，但首页不伪造尚未发布的文章链接。

## 验收标准

- 首屏 20 秒内可以回答：张靖远是谁、想做什么岗位、做过哪类项目。
- 每个项目页都能找到问题、个人动作、取舍、结果和反思。
- 不出现连续三个结构相同的口号式标题。
- 不用抽象名词代替项目事实。
- 所有数字、公司名、时间和职责与现有简历一致。
- 桌面端和移动端不因文案变长产生溢出、遮挡或首屏信息断裂。
- 站内链接、下载文件和邮件链接均可用。

## 资料依据

- Zara Zhang 个人网站：从个人经历、实际需求和鲜明判断出发，而不是先列技能标签。
- OpenAI, *A practical guide to building agents*：先判断任务是否需要 Agent，用 eval 建立基线，优先单 Agent 和清晰工具，必要时再增加复杂度。
- Anthropic, *Building Effective AI Agents*：优先简单、可组合、可调试的工作流，并重视工具接口对模型的可理解性。
- Anthropic, *Demystifying evals for AI agents*：评测应结合代码、模型和人工评分，并区分能力与回归评测。
- 2026 年 6 月可见岗位：OpenAI Product Manager, API Agents；Anthropic Product Manager, Claude Code Model Performance；Google Product Manager, Workspace Search 等，均强调 Agent 质量、自动评测、模型表现或复杂发布能力。
