# 首页首屏重构设计

## 背景

当前首页具有明确的纸张质感、杂志式排版和漫画头像，但首屏先表达产品观点，核心经历、能力证据和外部展示入口出现得较晚。招聘方快速浏览时，不容易在 10 秒内回答三个问题：张靖远是谁、能做什么、有什么证据。

本次重构采用“精细版 A”：保留现有视觉资产和个人气质，重排首屏信息顺序，使招聘方首先理解主身份，再看到差异化能力和可信证据。

## 目标

- 首要受众是招聘方和业务负责人。
- 访客在 10 秒内理解：张靖远是一名具备实现能力的 AI 产品经理。
- “AI 产品经理”是主身份，“AI Builder”是差异化能力标签。
- GitHub 和 X 从页尾联系方式提升为首屏能力证明入口，但不抢占项目主叙事。
- DeepWisdom 在首屏承担最强经历证明和视觉过渡作用。
- 保留现有漫画头像、纸色背景和杂志感。

## 非目标

- 不把首页改造成开发者作品墙。
- 不在首屏新增 GitHub 仓库卡片。
- 不恢复此前删除的 Agent Architecture 仓库内容。
- 不新增全局数字指标条。
- 不在本次改动中处理分享卡片、JSON-LD、导航滚动高亮、站内文章导读或项目详情页导航。
- 不重新设计项目卡片、产品观、写作、认可和联系区。

## 信息架构

首屏按以下顺序呈现：

1. 求职状态与基本信息。
2. 姓名。
3. 主身份与差异化标签。
4. 事实优先的简介与产品视角。
5. 两个主操作按钮。
6. GitHub 和 X 文字入口。
7. 漫画头像。
8. DeepWisdom 亮点条。

首屏后的下一屏呈现：

1. 产品能力与实现能力两列证据条。
2. 压缩后的个人背景介绍。
3. 随后进入现有精选项目区。

旧 About 四段文字不再作为首屏中的独立大文本块。旧 metrics-strip 整体删除。

## 首屏内容

### 求职状态

文案：

> 实习与校招机会开放 · 2027 届 · 北京

沿用现有状态点。状态必须使用真实、可长期维护的表述，不绑定已经过期的具体招聘批次。

### 标题层级

姓名继续作为最大字号标题：

> 张靖远

身份行：

> AI 产品经理 / AI Builder

视觉层级：

- “AI 产品经理”约 22px、较高字重、使用品牌蓝。
- “/ AI Builder”约 16px、常规字重、使用较浅的蓝灰色。
- 两者位于同一基线，但不能形成同等视觉权重。

### 简介

定稿文案：

> 做过 4 个从问题定义到验收指标的 AI 产品项目。关注的不是 AI 能不能生成，而是生成之后如何验收、修改，以及失败后如何恢复。

第一句先给事实，第二句再表达差异化产品视角。

### 主操作

保留两个主按钮：

- 查看精选项目 ↓
- 下载中文简历

按钮继续沿用现有主次样式。首页不增加第三、第四个按钮。

### 外部展示入口

在主按钮下方增加两个文字链接：

- GitHub @to-real ↗：`https://github.com/to-real`
- X @Potatoloogs ↗：`https://x.com/Potatoloogs`

链接使用细下划线和现有品牌蓝，视觉权重低于按钮、高于正文。外链在新标签页打开，并保留明确的键盘焦点状态。

### 漫画头像

保留现有头像、尺寸比例和拱形容器。桌面端继续作为右栏视觉锚点，不用 GitHub 卡片替换头像。

## DeepWisdom 亮点条

亮点条位于首屏主体下方，替代旧 metrics-strip，横向展示项目说明与三个指标。

项目名：

> DeepWisdom · Agent Evaluation Harness

职责说明：

> 参与评测系统建设，具体负责评测 Schema、自动检查与长任务恢复机制。

链接：

> 查看核心案例 →

目标路径：`projects/deepwisdom.html`

指标：

- 200+ 并行任务
- 70% 工作量降低
- 25% 成功率提升

“参与”说明团队背景，“具体负责”明确个人贡献边界。三个指标只在该亮点条出现一次，不在首屏重复。

## 能力与背景区

该区位于 DeepWisdom 亮点条之后、精选项目之前，使用两列能力结构。

产品能力：

> Agent 评测系统 · Harness Engineering · PRD · 用户研究

实现能力：

> Python · RAG · JSON Schema · Three.js · 视觉 AI

背景文案：

> 北邮数字媒体技术 2027 届。从代码转向产品，更关心“该不该做”和“做完如何验收”。持续做开源工具和技术写作。

该区不是标签云。两列必须保持对照关系，用结构表达“产品判断 × 实现能力”。

## 指标内容的去向

- DeepWisdom 的 200+、70% 和 25% 仅保留在亮点条。
- FunloomAI 的 30,000+ 用户和 7 日留存 61% 继续保留在对应项目卡片及详情页。
- “2 项软件著作权”继续保留在认可或项目语境中，不再出现在首屏。
- 不新增替代版全局 metrics-strip。

## 响应式行为

### 桌面端

- 维持左侧文案、右侧头像的双栏结构。
- DeepWisdom 亮点条为横向布局：项目信息在左，三个指标在右。
- 能力区为等宽两列。

### 平板端

- 首屏可降为单列，文案优先、头像随后。
- 主按钮允许换行。
- GitHub 与 X 保持为独立文字链接。
- DeepWisdom 项目说明占整行，三个指标在下一行平均分布。

### 移动端

- 顺序为状态、姓名、身份、简介、按钮、外链、头像、DeepWisdom 亮点条。
- 两个主按钮可使用现有全宽样式。
- 外链应换行或并排显示，但不得产生横向滚动。
- DeepWisdom 指标使用紧凑网格或纵向列表，不能压缩到难以阅读。
- 能力区由两列改为纵向两组。

## 可访问性与交互

- 保留头像替代文本。
- 所有链接必须能通过键盘访问。
- GitHub、X 和 DeepWisdom 案例链接必须有可见的 hover 与 focus-visible 状态。
- 外链使用 `target="_blank"` 时同时添加安全的 `rel` 属性。
- 不以颜色作为唯一交互提示；文字链接继续使用下划线。
- 保留 `prefers-reduced-motion` 兼容行为。

## 技术边界

该设计使用现有静态 HTML、CSS 和少量原生 JavaScript，不引入依赖或数据接口。所有信息是静态内容，不需要加载 GitHub API 或 X API，因此不存在外部接口失败导致首屏缺失的问题。

## 验收标准

- 首屏主身份明确为“AI 产品经理”，AI Builder 为次级标签。
- 首屏能看到求职状态、项目入口、简历入口、GitHub 和 X。
- DeepWisdom 职责说明与三个指标在同一亮点条内完整显示。
- 页面中不再存在旧 metrics-strip。
- About 由四段压缩为能力区后的短背景文案。
- DeepWisdom 的 200+、70% 和 25% 不在首屏重复。
- 1440px、1024px 和 390px 宽度下无横向溢出。
- 所有新增链接指向正确地址，并具有 hover 和键盘焦点反馈。
- 移动端阅读顺序与视觉顺序一致。
- 现有项目、产品观、写作、认可和联系内容不发生非必要变化。

## 验证方法

- 检查 HTML 文案和链接目标。
- 检查 CSS 在桌面、平板和移动断点下的布局。
- 在键盘模式下检查按钮、GitHub、X 和案例链接焦点。
- 确认页面只出现一组 DeepWisdom 首屏指标。
- 对比改动前后截图，确认现有头像、纸张质感和杂志式视觉语言得到保留。
